# 安全机制与验证

检查日期：2026-11-08。本文描述当前代码的防护与已完成验证。自动化回归测试使用临时数据库和模拟存储；公网部署检查验证新建管理员会话，不读取用户真实文件或分享。

## 登录与会话

- 登录按“规范化帐号＋来源”分别预留尝试次数，15 分钟最多 10 次；来源另有每分钟 60 次请求上限。成功后只清除相应帐号与来源的失败计数，其他帐号不共享低阈值计数。
- 来源地址统一由 `common/limits.py` 处理，仅信任 `TGPAN_TRUSTED_PROXIES` 列出的直接代理或代理链；其他连接忽略转发头。Nginx 必须覆盖外来转发头，部署步骤见 [运行与部署](deployment.md)。
- 密码验证后，在创建会话的同一 SQLite 写事务中重新核对密码哈希及禁用状态。密码重置或禁用发生在验证期间时，旧请求不能创建新会话。
- 修改密码和管理员帐号写操作在提交前复核凭据快照，防止在途操作覆盖管理员已重置的密码。修改/重置密码、禁用帐号仍撤销已有会话。
- 私人密码运算全站最多 4 个并发，同一登录组合或帐号修改操作最多 1 个；公开分享密码验证全站最多 2 个、同一分享与来源最多 1 个并发。忙时返回 429，不建立无界等待队列。
- 会话令牌随机生成，数据库保存摘要；Cookie 使用 HttpOnly 和 SameSite。HTTPS 部署必须开启 Secure，写操作验证来源与 CSRF，不开放跨域 CORS。

## 上传与连接测试

- 全站最多同时接收 2 个 HTTP 分块，每个帐号最多 1 个。接收前预留临时空间，覆盖 `.incoming` 文件与追加时的额外占用；超过容量立即返回带 Retry-After 的 429。
- 请求体在全局修改锁之外接收，120 秒超时；全局锁只用于短时间校验、额度预留及落盘提交。慢速上传不阻塞批量移动、分享撤销或上传取消。
- 提交时重新检查登录状态、任务状态及偏移。取消/清理任务之后，旧接收请求不能重新提交。成功、异常、超时或断开均释放预留容量及临时接收文件；正在接收的任务不会被无活动过期清理误删。
- 连接测试有独立并发限制：全站 2 个、每个帐号 1 个，90 秒超时。网络操作不持有全局修改锁；测试期间通过占用标记阻止配置被删除，结束时释放标记。

## 公开入口与文件读取

- `/api/docs` 和 `/api/openapi.json` 默认返回 404；仅本地开发需要时显式设置 `TGPAN_ENABLE_API_DOCS=true`，启用时标题为 Pan。
- 公开下载/预览的初始存储故障返回“文件暂时无法读取，请稍后重试”，不包含存储提供方、Token 或频道诊断。私人入口保留经过清洗的诊断。
- 文件与配置查询检查所属帐号；管理员不能通过网盘接口浏览其他用户的私人文件。SQL 使用参数化，静态资源检查解析后的路径仍位于静态目录。
- HTML/SVG 不作为在线预览提供。媒体使用类型白名单、nosniff 和 sandbox；下载文件名编码后写入响应头。
- 分享密码授权与私人帐号会话分开；取消、过期、回收站及帐号禁用都会影响公开访问，流中持续复查授权。分享返回 no-referrer 与不索引头。
- 将分享品牌改为 Pan 并不承诺对高级技术分析完全隐藏实现；静态前端代码仍可能包含私人管理功能的技术术语。公开入口不返回真实存储凭据。

## 依赖防护

`@heroui/theme` 的间接依赖 `deepmerge@4.3.1` 对应 [GHSA-gcqx-w48m-w2h4 / CVE-2026-93753](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)。检查时上游公告未列出修复版本，本项目通过 `frontend/patches/deepmerge@4.3.1.patch` 缓解：

- 在目标与来源两侧忽略 `__proto__`、`constructor`、`prototype` 等特殊键。
- 同时修补源文件及 CJS/UMD 发布入口，由 pnpm 锁文件固定补丁哈希。
- Docker 在安装前复制补丁目录；本地与镜像构建均使用同一依赖配置。
- `pnpm test:security` 验证两种入口的恶意输入被拒绝，并验证普通嵌套主题、数组和 Symbol 属性正常合并。

上游包版本仍为 4.3.1，npm 审计按版本匹配时仍可能报告此告警；不能据此宣称上游已修复或审计零告警。补丁是项目维护的缓解措施，后续采用上游正式修复时应重新评估并移除相应本地补丁。网站访客输入未发现进入主题构建插件的路径。

Python 锁文件中的 31 个依赖版本已使用 OSV 查询，未匹配到已知公告。该结果只代表查询时的数据库记录，不保证依赖没有未知漏洞。

## 验证

- 72 项 Python 测试通过，包含原有上传/下载、权限和分享测试，以及 11 项安全回归测试。
- 安全回归覆盖未知帐号登录不阻断其他帐号、可信/伪造转发头、密码重置或禁用时的在途登录、修改密码与管理员重置的竞态。
- 在暂停上传请求体期间验证分享撤销、上传取消及永久清理及时完成；释放请求体后旧请求不能提交，容量与临时文件清理正确。
- 两个不同帐号可同时接收分块，第三个接收被拒绝，临时空间预留与结束释放正确。
- 慢速连接测试不阻塞分享操作；测试中的配置不能删除，重复测试立即返回 429，结束后释放占用。
- 默认公开文档返回 404，公开与私人读取错误隔离。
- 前端 4 项依赖补丁测试通过，生产构建和冻结锁文件安装通过。

## 部署边界

公网部署需要 HTTPS、Secure Cookie、精确的公开来源和正确的可信代理地址；不要照抄其他机器的 Docker 网关。dedione 原生部署已启用这些设置，通过 Caddy 覆盖转发头并仅信任回环代理。初始管理员使用随机口令，仅保存在服务器 root 可读的文件中；未重置已有管理员密码。

dedione 已验证真实 TLS、HTTP 到 HTTPS 跳转、后端仅监听回环、管理员登录及 Cookie/来源校验。未做操作系统和防火墙的全面审计，也未验证真实 Telegram 大文件传输。本次检查与回归测试不是完整渗透测试或安全保证。
