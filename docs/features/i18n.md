# 多语言国际化

界面支持简体中文和英文，登录、文件、回收站、上传队列、设置、用户管理、分享管理、公开分享页及其弹窗、通知和无障碍标签均使用同一语言规则。

页面加载时按 `navigator.languages` 的偏好顺序选择第一个支持的语言；该列表不可用或为空时使用 `navigator.language`。`zh` 及其地区/文字变体（如 `zh-CN`、`zh-TW`、`zh-Hant-HK`）统一使用简体中文，`en` 及其地区变体使用英文；没有匹配项时使用英文。更改浏览器语言偏好后刷新页面生效。当前没有独立语言切换或帐号语言设置。

日期、时间、数字与 HeroUI 组件语言跟随选中的语言，时区仍使用访问者设备的本地时区。HTML 的 `lang` 和页面描述也同步设置。

前端 API 请求显式发送选中语言的 `Accept-Language`，确保界面和接口错误一致。后端直接调用及浏览器下载/预览请求按 `Accept-Language` 协商，考虑 `q` 权重，排除 `q=0` 和无效权重，未匹配或未提供语言时使用英文。API 响应包含 `Content-Language` 和 `Vary: Accept-Language`；错误状态码和 `Retry-After` 等响应头保留，输入校验失败统一返回本地化的 422 提示。

文件名、目录名、帐号名、配置名、频道名和用户自定义分享标题属于用户数据，不翻译。未填写分享标题时，中文创建请求保存“好东西”，英文创建请求保存“Shared files”；已有分享的标题按保存值展示。分享链接附带复制的密码标签使用创建者当前界面语言。

后端后台任务保存原始诊断文案，在接口返回时翻译 `error` 字段；同一任务可被不同语言的请求读取，不改写数据库。存储测试只翻译步骤名称和系统诊断，频道名与机器人名保持原样。

## 开发维护

- 前端公共模块为 `frontend/src/i18n/`。采用中文源文案作为翻译键，英文目录集中在 `en.ts`，`t()` 使用类型检查保证键存在。插值使用 `{p0}`、`{p1}`，完整句子一起翻译，用户数据只做一次替换并由 React 转义。新增语言时扩展目录、匹配规则及格式化语言；业务代码不维护翻译字典。
- 后端公共模块为 `backend/app/common/i18n.py`，英文目录位于 `common/locales/en.py`。异常在统一处理器翻译，持久化诊断只在返回接口时翻译，避免将请求语言写入任务数据。新增接口提示时同步补充英文目录。
- 上传队列使用固定状态标识，页面单独翻译状态名称，暂停、续传和过滤逻辑不依赖显示文案。
- 在 `frontend` 执行 `pnpm test:i18n`、`pnpm test:security` 和 `pnpm build`；在 `backend` 执行 `uv run pytest -q`。国际化测试覆盖语言优先级、英文回退、目录覆盖、占位符、请求语言、日期格式、后端校验与错误、后台诊断及用户数据保留。
