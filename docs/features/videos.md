# 视频下载

## 页面和任务

侧栏“视频下载”与“离线下载”分开显示。新建任务支持每行一个公开视频或播放列表链接，单次最多 20 个，覆盖 yt-dlp 支持的网站，包括 B 站与 YouTube。源站的区域、登录、会员权限、反机器人措施和组件版本会影响能否下载，不承诺所有链接均可用；不支持直播及尚未开始的视频。

选择网盘目标目录、Telegram 存储和可选 Cookie 后解析视频。新建任务解析完成后自动打开“选择视频和画质”，也可在列表点击该按钮，查看视频标题及已知时长，勾选分 P 或播放列表条目。每个链接最多解析前 200 项，超过时请拆分来源链接。画质可选最佳、2160p、1440p、1080p、720p、480p、360p，选择不超过目标高度的最佳可用格式，也可仅下载音频。播放列表中的每个视频在下载前重新解析实际媒体地址，避免长期保存易失效的下载地址。

单视频以标题命名，多集保存到以播放列表标题命名的目录，文件名前加分集序号；同名目录复用，同名文件自动编号保留两份。视频尽量合并为 MP4，编码无法容纳时保留 MKV；合并不主动重新编码。音频提取为 M4A，必要时由 ffmpeg 转码。浏览器能否播放取决于实际容器和编码，MKV 沿用普通文件下载行为。

任务复用公共调度和分块上传队列，展示下载到服务器、存入 Telegram 两段进度，以及排队、解析、等待选择、下载、合并处理、转存、完成或失败状态。支持暂停、继续、重试、取消、打开目录及删除已结束记录。下载续传依赖 yt-dlp 和源站；合并中暂停后可能重新合并，Cookie 失效可先更新配置再重试。网页关闭后仍继续，服务重启后恢复活动任务，手动暂停的任务仍暂停。禁用用户会停止其任务。

## Cookie 管理

页面顶部“Cookie 管理”按钮打开弹窗，支持添加、更新和删除配置。填写名称、网站域名（例如 `bilibili.com` 或 `youtube.com`），粘贴浏览器 Cookie 请求头（`name=value; name2=value2`，也接受 `Cookie:` 前缀），或 Netscape cookies.txt 内容。Netscape 内容中的 Cookie 域名必须与配置域名一致；只导出所需网站域名的数据，不接受包含多个其他域名的整个浏览器 Cookie 文件。

Cookie 属于当前用户，Fernet 加密保存，列表与编辑均不回显内容；更新时重新粘贴。新建任务选择配置，初始链接必须与该域名或子域名匹配，另支持 YouTube 的 `youtu.be` 和 B 站的 `b23.tv` 短链接。下载时将 Cookie 转成域名受限的 Netscape 临时文件，以 0600 权限保存在私有临时目录，通过 `--cookies <路径>` 传入命令；命令结束、失败或取消时删除，服务启动时也会清理异常退出遗留的 Cookie 临时目录，不将 Cookie 内容放进命令参数、API 返回值或错误信息。

未结束任务引用的 Cookie 不能删除，可以更新后重试；更新配置会作用于后续命令，已经运行中的命令使用其启动时的 Cookie 快照。Cookie 不能绕过帐号本身的访问权限。

## 元数据和文件索引

任务“视频详情”展示来源网站、视频 ID、原始链接、标题、作者、发布时间、时长、封面地址、简介、字幕语言和格式，以及下载后的画质、编码、大小与容器。存在 ffprobe 时读取本地成品，补充实际编码、分辨率、帧率和时长。封面以源站 URL 展示，字幕保留语言和格式描述，不额外下载封面或字幕文件；源站地址失效后封面可能无法加载。

实际文件沿用 `nodes/uploads/blocks` 存储，`uploads.origin=video`，视频任务通过公共离线任务记录持久化，附加配置和元数据存入 `video_tasks/video_entries`。元数据在创建上传记录的同一事务中关联网盘文件；任务记录删除后仍可在“我的文件 → 视频详情”查看，永久删除网盘文件时删除关联元数据。普通离线任务列表和浏览器传输弹窗不重复显示视频任务。

每块 Telegram 的消息 ID、file_id、SHA256 和文件索引提交成功后才删除本地成品；全部转存完成后删除任务目录。暂停、失败保留可续传内容，取消清理未完成文件及已知远程块，已经完成的文件保留。删除任务记录不删除网盘文件。

## 组件与资源

管理员在“设置 → 视频下载组件”分别检测、安装和更新 yt-dlp、ffmpeg，展示版本、来源、路径、安装状态和失败原因。优先使用数据目录中的应用管理版本，没有时检测 PATH 中的系统命令。

yt-dlp 和 ffmpeg 均为独立命令，项目不 import yt-dlp，也不把它加入 `pyproject.toml` 或 `uv.lock`。安装复用组件管理器，在数据目录使用 micromamba 和 conda-forge 创建独立运行环境；yt-dlp 环境同时安装 Deno 供其 JavaScript 解析使用。安装验证成功后原子切换，失败保留原版本。组件安装串行执行，有活动下载或转存时须先暂停，安装期间不启动新任务。支持平台与 aria2 管理一致。

视频任务与普通离线任务共用管理员设置的下载并发、离线空间上限和磁盘保留空间，单文件沿用 `TGPAN_MAX_FILE_SIZE`。下载与合并时监测临时空间，视频、音频流和合并结果可能同时存在，因此须预留成品大小数倍的磁盘空间。限额检查是周期性的，并非操作系统硬配额。

通过参数数组启动子进程，不使用 shell；禁用用户 yt-dlp 配置与插件目录，不读取浏览器 Cookie 或 netrc。HTTP/HTTPS 请求通过带临时凭据的本机转发器，逐次验证公网目的地址并连接已验证 IP，阻止访问本机、内网和保留地址；原生 DASH/HLS 下载后由本机 ffmpeg 合并。视频下载不继承环境 HTTP 代理，也不使用 Telegram 的 `TGPAN_PROXY_URL`。

## 验证边界

自动化测试覆盖模拟视频解析与真实 Telegram 分块队列、播放列表勾选和目录、音频模式、元数据保留、Cookie 加密和用户隔离、大小限制、暂停取消、失败重试、临时 Cookie 文件清理、调度重启恢复及手动暂停状态保留；安装系统 yt-dlp 和 ffmpeg 时额外运行真实命令下载本地生成的视频，并校验转存回读内容。Telegram 使用模拟存储，不能据此推断真实频道速度和稳定性。

参考：[yt-dlp 官方命令说明](https://github.com/yt-dlp/yt-dlp#usage-and-options)、[网站提取器与 YouTube Cookie 说明](https://github.com/yt-dlp/yt-dlp/wiki/Extractors)。

本次使用 ego-browser 验证桌面与 390px 手机布局、Cookie 添加和选择、解析后自动打开选择弹窗，以及 W3Schools 公开视频通过真实 yt-dlp 下载后完成模拟 Telegram 转存。尚未使用真实 B 站/YouTube 登录 Cookie 和真实 Telegram 频道验收。
