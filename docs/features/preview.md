# 图片与视频预览

已完成上传且未在回收站的媒体文件，可点击文件名称或行内“预览”图标打开弹窗。旧文件自动按当前名称识别，无需重新上传。弹窗保留“下载原文件”按钮，其他格式仍按原流程下载。

## 支持格式

- 图片：JPG/JPEG、PNG、GIF、WebP、AVIF、BMP，适应窗口显示。
- 视频：MP4/M4V、WebM、MOV、OGV，使用浏览器原生播放器，支持播放/暂停、音量、全屏及拖动进度条。

扩展名只用于识别预览类型，实际能否解码取决于文件内容和浏览器。MP4 推荐 H.264/AAC，WebM 推荐浏览器支持的编码；MOV、OGV 等在不同浏览器上支持程度不同。HEVC、MKV、AVI、HEIC 等不保证可预览。没有引入服务端转码、缩略图生成或视频处理依赖，不增加 VPS 的转码 CPU 负担。播放失败时页面提供重试与下载提示。

HTML、SVG、PDF、文档及压缩包暂不提供 inline 预览，仍可下载。

## 流式读取和拖动进度条

`GET /api/files/{id}/preview` 以 inline 和指定媒体 MIME 返回内容，支持单范围 Range、尾部 Range、206 Content-Range/Content-Length/Accept-Ranges，以及 HEAD 元数据请求。HEAD 不向 Telegram 下载内容。

浏览器拖动进度条后会按视频索引发起新的范围请求，后端将逻辑偏移映射到 Telegram 存储块，按需流式读取。带 Range 的单次预览最多返回 4MiB，浏览器继续请求后续数据；不要求先下载完整视频。普通下载不受这个 4MiB 响应上限影响。

预览最多同时进行两个流式读取，普通下载另有一个名额，均使用有界缓冲。播放器关闭时移除视频源并取消待处理请求。活动预览与下载使用引用计数，防止多个请求并存时过早允许永久删除文件。

如果 Telegram 文件服务器忽略 Range，应用会流式跳过块前部，仍可提供逻辑范围，但跳转可能需要额外带宽及等待；网络速度、远端限流、关键帧间隔和视频索引位置也会影响跳转速度。MP4 索引在文件尾部时，浏览器可能先请求尾部元数据。

## 权限

私人文件预览要求登录，仅本人可读取自己的活动文件，回收站与未完成文件不能预览。分享页使用独立的分享链接和密码授权，同样检查到期、取消及原文件状态。浏览器只请求后端 URL，不接触 Bot Token 或 Telegram 文件下载链接。响应设置 no-store、nosniff 与 sandbox，不允许把不受支持的可执行格式直接内联打开。
