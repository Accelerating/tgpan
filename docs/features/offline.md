# 离线下载

## 创建和查看任务

侧栏“离线下载”提供服务器下载功能。支持每行一个的 HTTP/HTTPS 直链、磁力链接或远程 `.torrent` 地址，单次最多 20 个链接；也可上传一个不超过 8MiB 的本地种子。下载链接只支持无需额外登录的地址，首版不提供 Cookie、自定义 Header、下载代理或 m3u8 合并，不依赖 ffmpeg。

创建任务时选择网盘目标目录和 Telegram 存储配置，默认使用自己的默认配置。BT/磁力先解析文件清单，再勾选需要的文件；默认全选，可调整后开始。支持 BitTorrent v1 和包含 v1 信息的混合种子，不支持纯 v2、符号链接和不安全路径。保留种子目录结构，已有同名目录会复用，同名文件自动编号保留两份。

每个用户只能查看和操作自己的任务。任务列表分别显示“下载到服务器”和“存入 Telegram”的进度、已完成大小、速度及预计剩余时间；未知大小时显示不定进度，获取总大小后更新。aria2 进度以完成的数据块为准，小文件可能在完成前一直显示 0%。转存速度按最近约 8 秒的发送字节变化估算，并不代表 Telegram 已确认的持久化速率。关闭网页不会停止任务。

提供暂停、继续、重试、取消、选择文件、打开目标目录以及删除已结束记录。暂停会停止 aria2 子进程并保存其控制文件；转存暂停后不再发送下一块，已经发送中的 Telegram 块可能正常完成。HTTP 续传依赖源站支持 Range 和资源保持一致；源站不支持时任务可能失败，需要取消后重建。服务重启后恢复活动任务，手动暂停的任务保持暂停。禁用用户会暂停其离线任务。

## 大小和磁盘空间

单文件沿用 `TGPAN_MAX_FILE_SIZE`，默认 5,000,000,000 字节。HTTP 预检已知大小超限时不创建任务并弹窗提示；BT 在选择文件时检查所选文件。下载过程中发现超限会停止下载并记录失败，网页弹窗提示，本地超限内容清除。未知长度不表示没有大小限制。

管理员可在“设置 → 离线下载组件”调整：

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 同时下载任务数 | 1 | 1～4 个 aria2 下载或元数据解析任务 |
| 离线空间上限 | 10GiB | 离线任务预留容量和本地文件的上限 |
| 磁盘保留空间 | 512MiB | 下载期间须保留的文件系统可用空间 |

完整下载的文件保存于 `TGPAN_DATA_DIR/offline/<任务 ID>/contents/`，另保留种子及 aria2 续传控制文件。视频下载与本模块共用下载并发、离线容量和磁盘保留空间限制，详见[视频下载](videos.md)。离线容量独立于浏览器上传的 `TGPAN_TEMP_LIMIT`；转存时仍遵守公共上传临时空间限制。后台定期检查实际文件大小和磁盘可用空间，容量不足时停止任务并显示原因；这些检查不是操作系统硬配额，检查间隔内可能出现少量超额写入。

普通 HTTP/HTTPS 请求经过仅监听回环地址、带临时凭据的进程内转发器，对每次目标（包括重定向和 HTTPS CONNECT）检查解析地址，并连接已检查的数值 IP，禁止本机、内网和保留地址。BT 的 DHT、Peer 和 UDP tracker 属于直接的 P2P 流量，不经过 HTTP 转发器。aria2 不继承服务进程的 HTTP 代理变量，也不读取用户 aria2 配置或 netrc。Telegram 仍使用独立的 `TGPAN_PROXY_URL` 配置。

## 转存和本地清理

每个任务下载完成后进入转存队列，一次导入一个文件，复用 `uploads`、`blocks`、`nodes` 和现有 Telegram 后台发送器。每次最多准备一个存储块，不把整个文件装入内存，也不另建 Telegram 上传通道。

成功保存每块的消息 ID、file_id、SHA256，并在事务中把逻辑文件标记为可用后，才标记该离线文件完成并删除原始本地文件。每个已完成文件立即可供普通预览、下载和分享。多文件任务全部转存后删除整个任务临时目录；下载完成后停止做种，下载期间仍可能向其他 Peer 上传数据。

失败和暂停任务保留文件与进度，直到手动继续、重试或取消，不套用浏览器上传的 24 小时过期清理。重试转存会复用原上传记录及已经成功的块，本地暂存块缺失时可从保留的完整文件重建。取消删除本地内容、取消未完成文件的上传并排队清理已知 Telegram 块；已经完整转存的文件保留。删除任务记录不删除网盘文件。

启动时清理已经结束任务遗留的本地目录，以及已完成文件遗留的原始文件。文件索引和任务状态持久化在 PostgreSQL 中，任务来源加密保存，不在列表接口返回。Telegram 跨系统事务仍存在原有极短窗口：Telegram 已接收但消息 ID 尚未写入数据库时崩溃，频道可能留下孤立附件。

## aria2 管理

管理员可检测 aria2 是否安装、查看版本与路径，安装应用管理版本或更新应用管理版本。普通用户不能安装组件或调整全局资源设置。

优先使用 `TGPAN_DATA_DIR/components/aria2/bin/aria2c`，没有应用版本时检测 PATH 中的 `aria2c`。安装使用官方 micromamba 引导程序和 conda-forge 的 aria2 包及运行库，在数据目录创建独立环境，无需 root，也不修改系统已有软件或 shell 配置。支持 glibc Linux x86_64/ARM64 和 macOS Intel/Apple Silicon；其他系统可手动安装并确保服务 PATH 可见。

更新创建新环境，运行 `aria2c --version` 验证成功后原子切换符号链接，再移除旧环境；失败继续保留原版本。正在运行离线或视频任务时拒绝更新，需先暂停任务。安装状态和失败原因可在网页查看；安装阶段显示状态与不定进度，不展示虚构百分比。服务停止会结束其启动的安装或下载子进程。

后端通过参数列表直接运行系统命令并读取标准输出，不使用 shell 拼接，不启用或暴露 aria2 RPC，也不要求外部 aria2 守护进程。

## 验证边界

自动化测试涵盖 HTTP 转存、BT 勾选与目录结构、磁力元数据流程、超限、失败重试、暂停继续、进程重启恢复、权限和更新失败保留旧组件。安装了 aria2 时额外运行真实 HTTP 下载与进度读取测试，Telegram 使用模拟存储。dedione 上已验证 Linux 安装、管理员 API 安装、HTTP 下载、临时 tracker/真实做种进程的 BT 和磁力下载，以及真实 Telegram 多块转存和 SHA256 回读校验。下载源的 Peer 可用性和源站续传能力由外部服务决定；5GB 文件的完整传输尚未实测。
