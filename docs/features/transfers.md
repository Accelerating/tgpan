# 上传、下载与任务恢复

## 上传

上传文件、文件夹或拖放上传后停留在当前目录，并提示已加入队列的文件数量。切换页面不影响浏览器上传；上传完成只更新文件列表和显示提示，不自动跳转。

“我的文件”标题旁提供“传输任务”按钮，并显示未结束任务数量，点击打开任务弹窗。侧栏不再提供独立传输页面；有未结束任务时，页面底部提供常驻传输入口，点击打开同一个弹窗。弹窗打开时隐藏底部进度条，关闭后恢复；关闭弹窗不影响上传，当前目录、搜索、排序和滚动位置保持不变。底部进度条分别汇总“上传到服务器”和“存入 Telegram”的进度，并提示暂停或失败任务。数量合并本地队列与服务器记录，同一任务只计算一次；已完成、取消或过期的任务不计入。只有服务器确认文件已全部存入 Telegram 才提示完成。进度按当前未结束任务的总字节计算，任务完成或新增后会重新计算。暂停、续传、重试、取消和 Telegram 原文件清理均在弹窗内操作。任务列表在弹窗内部滚动，标题与关闭按钮保持可见。

本地队列和服务器上传记录都提供“打开所在目录”，按各任务自身的目标目录定位，同时关闭弹窗并显示该目录；打开当前目录保持原浏览位置。

文件页的“上传文件夹”可选择本地文件夹，保留所选根目录及其内部文件相对路径，上传到当前网盘目录；也可将一个或多个文件夹与文件一起拖入文件页。拖放递归读取全部目录条目，只为实际文件创建必要的父目录，跳过空目录（包括仅包含空子目录的目录树）。完全空的文件夹不能上传，会显示提示，不创建网盘目录或上传任务。

上传前通过 `/api/files/folders/resolve` 一次性准备目录映射，同名活动目录直接复用，方便重新选择文件夹后续传；同名文件阻挡目录路径时整体返回冲突，不创建半套目录。目录名沿用普通目录的校验与 NFC 规范化，禁止绝对路径、空路径段和 `.`、`..`。单次请求最多 5000 条目录路径，解析后的目录总数（包含父目录）也不能超过 5000，每条路径最多 4096 字符、100 层。目录准备完成后各文件进入现有分块上传队列，文件重名仍逐文件选择“保留两份/取消”，不会覆盖已有文件。上传失败、暂停或取消不自动删除已准备好的目录；单个文件仍可在传输任务弹窗继续或取消。

单文件最大 5,000,000,000 字节。浏览器按文件顺序上传，每个 HTTP 分块默认 4MiB；后端组合成默认 16MiB 的存储块，再通过 Bot API 逐个发送到 Telegram。最后一个存储块可以较小。已转存成功的块及时从临时目录删除，因此上传 5GB 文件无需同时在 VPS 保存完整文件。

每个 HTTP 分块带 SHA256，长度、校验值和偏移全部通过后才确认接收。存储块另存 SHA256。文件选择指纹由文件名、大小、最后修改时间及首尾各 1MiB 内容生成，用于恢复时检查是否选择了原文件；该指纹不是整文件哈希，也不能识别只改动中间内容且伪装相同元数据的文件。续传应选择未改动的原文件。

临时上传空间默认上限 2GiB，检查时计入接收文件及追加过程的额外空间。达到限制返回 429，浏览器等待转存释放空间后再试。HTTP 单块接收有 120 秒超时。HTTPS 或 localhost 安全上下文是浏览器 SHA256 的前提。

全站最多同时接收 2 个 HTTP 分块，每个帐号最多 1 个；超出直接返回带 Retry-After 的 429，不排队。开始接收前在短临界区预留临时空间，网络请求体在全局修改锁之外写入独立 `.incoming` 文件，提交时重新检查登录、任务状态和偏移。慢速接收不阻塞移动、删除和撤销分享；取消后在途请求无法提交，结束、失败或断开都会清理接收文件与预留空间。正在接收的任务不按无活动过期处理。

页面分别展示“上传到服务器”和“存入 Telegram”。只有所有块成功存入 Telegram 后，文件才可以下载。浏览器支持暂停当前本地上传、网络失败有限重试、重名时保留两份/取消；转存失败需要在传输任务弹窗内点击重试。已传到服务器的内容在关闭页面后仍会继续转存。

刷新后重新选择原文件可继续上传，服务器确认的偏移是唯一依据。服务启动时把未结束的远程任务重新排队，并截断落盘但尚未确认接收的尾部。进程崩溃发生在“Telegram 已接收文件，但消息 ID 尚未写入数据库”的极短窗口时，可能在频道留下重复附件；第一版不承诺 Telegram 跨系统事务或完全无孤儿文件。

未完成且无活动超过默认 24 小时的接收/失败任务会被删除，关联临时数据清除，已知远程块进入清理队列；正在远程发送的块不按过期处理。已全部传到 VPS 并等待转存的正常任务不因这个期限失效。取消上传会清理本地块并安排删除已知远程块；在途远程块完成后也会追加清理。

## 下载

后端通过 Bot API getFile 获取临时下载地址，再读取有序块，按需拼接成流，以原逻辑文件名下载，不完整缓存文件。支持 HTTP 单范围 Range（包括尾部范围），方便浏览器或下载工具续传，图片和视频预览共用这套范围读取能力。Telegram 文件服务器支持范围响应时直接读取目标范围；如果返回完整文件，后端流式跳过前部数据，不把完整存储块装入内存。每次重新调用 getFile 取地址，数据库只长期保存 file_id。

单次只处理一个普通下载，预览另外允许两个并发读取请求，以便视频跳转及读取尾部索引。多余请求等待空闲名额，排队超过 60 秒返回 429，可稍后重试。下载进度与文件保存由浏览器管理，不在网页维护下载进度。

初始读取失败返回 JSON 错误；私人入口保留安全的存储诊断，公开分享入口只提示文件暂时无法读取。流已开始后发生网络异常会中断连接，浏览器需要重新下载或按 Range 续传；不能在已发送文件内容后再切换为 JSON。存储块 SHA256 记录用于后续完整性检查扩展，当前下载不先缓存整块进行预校验。

## 验证边界

自动化测试使用模拟存储验证多块拼接、范围读取、权限、恢复和错误处理。实际 Telegram 上传速度、限流及真实 5GB 传输需要使用部署者自己的凭据验收，不能从模拟测试推断真实网络性能。

## 离线来源的文件

服务器下载的 HTTP、磁力与 BT 文件由独立的[离线下载页面](offline.md)管理。下载完成后复用本模块的 Telegram 上传队列和文件索引，浏览器传输任务弹窗不重复展示这些记录。离线任务的暂停、重试、取消和保留期限由离线任务管理；其未完成上传不参与浏览器上传的自动过期清理。
